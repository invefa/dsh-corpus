## 功能

### 命令审批

每次调用 bash 或 pwsh 之前，插件先拿命令原文过一遍规则表。命中 allow 的直接执行，命中 ask 的挂起等你决定，命中 deny 的在开始之前就停下，并把命中的规则名和那段命令一起返回。

规则按顺序匹配，但不按顺序定结论。同一条命令如果同时命中几条规则，先看动作，deny 高于 ask，ask 高于 allow；动作相同时取最靠前的那一条。allow 与 ask 同时命中时，看哪条规则更具体，写得窄的那条说话，所以一条范围很小的 allow 可以放行删除构建目录这类常见操作，而不用为它关掉整条递归删除的 ask。

总开关在页面顶部。关掉以后规则仍留在原处，命令直接交给宿主原策略，与没有这道闸门时一致。规则表为空或全部停用时也是同样的结果，不会出现“没规则所以全拦”的情况。

### 等待与决定

命中 ask 的命令进入待批队列，按到达顺序排列，页面上能看到命令原文、命中的规则、来自哪个会话、排在第几位。同一个会话重复送同一条命令时不会多排一条，而是回到原来那一项，第一次的解释保留。

决定有四种：允许一次、本会话允许、永久允许、拒绝。允许一次只对这一条生效；本会话允许把这条规则记在会话上，会话结束即失效；永久允许会生成一条 allow 规则，写在规则表里，可以像其他规则一样停用或删除。拒绝与超时都会终止命令，并把原因一并返回。

默认等待 120 秒，可以在设置里改，改成 0 表示不限时。队列上限 20 项，满了以后新命令直接拒绝而不是静默放行。等待期间调用被取消，队列项记为已取消，不会留下一条无人能答的问题。

### 被拦下之后

任何一次拦截都会要求模型先说明这条命令做什么、为什么被拦、有没有更安全的写法，然后才谈下一步；在解释之前重试同一条命令或等价写法都不被鼓励。这段说明会被记录下来，挂在对应的待批项上，也进判定历史，可以在页面上展开看。

模型如果没解释就直接重试，第二次判定照常进行，历史里那一条标成未解释即重试。记录只标记，不阻断，避免把一个着急的重试变成死循环。

### 预置规则

随插件发一份预置规则，分两档导入。最小集 36 条，覆盖删根、写块设备、格式化、下载即执行、反弹 shell、读私钥、删库这类几乎不可逆的操作，以及安装依赖、改计划任务、强推、关机重启这类需要人看一眼的操作。扩展集 8 条，覆盖清历史、清事件日志、改写提交历史、改防火墙这类与审计相关的操作，默认不导入。

每条预置带平台标记，按当前系统过滤：Windows 上导入口令与注册表相关的规则，其他系统导入 shell 与挂载相关的规则。导入只补缺失项，你改过的同 id 规则保持原样，删掉的预置会重新出现，这是“缺则补”的代价，页面上的导入按钮会报告新增、跳过与失败三个数字。

### 补丁表

补丁按宿主的构建版本分组，构建不同则改动位置不同。每条规则列出状态：待应用、已生效、或对本构建不适用；打开规则先看它会改动哪些文件的哪几行，再决定是否启用。改动前每个文件都留原文备份，任何一处改动都能单独还原，也能成批还原到初始状态。

### 提示词与规则集

每一轮注入的操作者提示词由你自己维护的 Markdown 文件拼装，页面显示它在字符与词元上的规模，超过预期时能看出来。规则集是另一件事：把 Markdown 规则写进指定的工作区，在那里工作的代理读到的是文件本身，不必每轮重复交代。

### 技能

已安装的技能可以导出成包，也可以从包导入，列表能在页面上重新读取。导出的包带着技能的说明与内容，换一台机器可以接着用。

### 两种呈现

面板可以整页打开，也可以在聊天旁开一个小窗，两种呈现读同一份状态，切换时选中的规则与展开的区块不会丢。标签上显示等待审批的数量，没有待批时不显示；新命令出现时页面上会出一条可跳转的提示，关掉后同一条不再重复弹。

## 安装

1. 解压归档。
2. 把解压出的目录放进你这份 DSH 的 profile 目录。
3. 把插件加入该 profile，重启一次宿主。
4. 面板从侧栏的“规范库”入口打开。

## 更新

把新包解压覆盖旧目录，重启宿主。配置与规则状态存在插件目录之外，替换后仍在。

## 卸载

从 profile 里移除插件，删除其目录，重启宿主。

## 运行要求

- Windows。
- 与本版本对应的 DeepSeek Harness 桌面端。
